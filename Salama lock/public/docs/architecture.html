System design

Architecture

Layered architecture as implemented: Controller → Service → Queue → Provider → Repository → Database.

Layer rules

Documented in ArchitectureRules.java:

Controller  →  HTTP only (validate input, call service, return response)
     ↓
Service     →  business logic, transactions, orchestration
     ↓
Provider    →  external systems (MockGoogle / Google DLC) when needed
     ↓
Repository  →  persistence access
     ↓
Database

Request path: lock command

sequenceDiagram participant P as Partner participant C as CommandController participant S as CommandService participant DB as PostgreSQL participant W as CommandQueueWorker participant E as CommandExecutorService participant R as ProviderRegistry participant M as MockGoogleProvider P->>C: POST /api/v1/lock + JWT/API key C->>S: enqueueLock(principal, request, correlationId) S->>DB: resolve device, insert PENDING command S-->>C: CommandResponse C-->>P: 202 + Location + body loop every salama.queue.poll-interval-ms W->>E: claimBatch / processOne E->>DB: FOR UPDATE SKIP LOCKED → PROCESSING E->>R: activeProvider() R->>M: execute(ProviderCommandRequest) M-->>E: ProviderResult E->>DB: SUCCESS/RETRYING/FAILED + device status end P->>C: GET /api/v1/commands/{id} C->>S: getStatus S-->>P: status + pollAfterSeconds

Device registration sequence

sequenceDiagram participant P as Partner participant C as DeviceController participant S as DeviceService participant G as LockIdGenerator participant DB as PostgreSQL P->>C: POST /api/v1/devices (imei1/imei2/…) C->>S: register(principal, request) S->>DB: assert identifiers available (active devices) S->>G: generate SL-ULID S->>DB: insert devices + device_identifiers S-->>P: 201 DeviceResponse (lockId, status REGISTERED)

Unlock sequence

Same as lock, except CommandType.UNLOCK. On provider success, device status becomes UNLOCKED.

Command polling sequence

sequenceDiagram participant P as Partner participant C as CommandController participant S as CommandService participant DB as PostgreSQL P->>C: GET /api/v1/commands/{id} Note over P,C: Requires SCOPE_commands:read C->>S: getStatus(principal, id) S->>DB: findByIdAndCompanyId alt found S-->>P: CommandResponse (pollAfterSeconds if non-terminal) else missing / other company S-->>P: 404 COMMAND_NOT_FOUND end

Callback processing sequence

sequenceDiagram participant G as Provider/callback sender participant C as GoogleCallbackController participant S as GoogleCallbackService participant DB as PostgreSQL G->>C: POST /api/v1/callback/google + X-Callback-Secret C->>C: verifyCallbackSecret C->>S: handle(request) alt duplicate providerEventId S-->>G: 200 {status: DUPLICATE} else new event S->>DB: resolve device by lockId (IMEI fallback) S->>DB: save google_callbacks, apply event S-->>G: 200 {status: PROCESSED, deviceStatus} end

Provider execution sequence

sequenceDiagram participant E as CommandExecutorService participant REG as ProviderRegistry participant CFG as SystemConfigService participant M as DeviceLockProvider participant DS as DeviceService E->>REG: activeProvider() REG->>CFG: getValueOrDefault("provider.active", "MOCK_GOOGLE_DLC") REG-->>E: provider bean E->>M: execute(ProviderCommandRequest v1) M-->>E: ProviderResult alt success E->>DS: updateStatus LOCKED/UNLOCKED E->>E: command SUCCESS else retryable and retries left E->>E: RETRYING + nextRetryAt else terminal failure E->>E: FAILED end
